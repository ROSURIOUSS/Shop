# GameZone — интернет-магазин игровых аксессуаров

**GameZone** — многостраничный интернет-магазин игровой периферии на Django.
Это учебный проект для контрольной работы по Python и Django: реальный серверный
функционал (ORM, сессии, формы, CRUD, админ-панель), а не статическая вёрстка.

> Проект носит демонстрационный характер: товары, цены и контакты вымышленные,
> платёжная система не подключена. Заказы сохраняются в базе данных SQLite.

---

## Что реализовано

- **Каталог** с серверным поиском (`?q=`), фильтром по категориям, диапазоном цены,
  сортировкой и пагинацией (12 товаров на страницу).
- **Категории** — список и отдельные страницы категорий (`/categories/<slug>/`).
- **Карточка товара** — изображение, характеристики (JSON), наличие, похожие товары.
- **Корзина на сессиях** — добавление, изменение количества, удаление, очистка;
  цены всегда пересчитываются на сервере по данным базы.
- **Оформление заказа** — валидация формы, проверка остатков, создание `Order` и
  `OrderItem` с фиксацией цены, списание остатков — всё в одной транзакции.
- **Страница успеха** доступна только из сессии, в которой оформлен заказ.
- **Контакты** с формой обратной связи (сообщения сохраняются в БД).
- **Django Admin** — управление категориями, товарами, заказами и обращениями.
- **Адаптивный дизайн** (десктоп, планшет, смартфон), тёмная premium-тема.

## Технологии

- Python 3.12+, Django 6.1, SQLite
- HTML5, CSS3 (Grid/Flexbox), немного JavaScript (только UI)
- Django Templates, Django ORM, Forms, Sessions, CSRF-защита

## Запуск на Windows

### Быстрый способ (в один клик)

Дважды кликните **`run.bat`** — батник сам найдёт Python, подготовит окружение,
установит зависимости, применит миграции, добавит демо-товары (если база пуста),
предложит создать администратора и запустит сервер, открыв магазин в браузере.

| Файл | Что делает |
|---|---|
| `run.bat` | Полный запуск: окружение + зависимости + база + администратор (по желанию) + сервер + браузер |
| `run.bat 8080` | То же самое, но на другом порту — удобно, если 8000 занят |
| `create_admin.bat` | Отдельное создание администратора для входа в `/admin/` (логин и пароль вводятся видимым текстом) |

Что ещё делает `run.bat`, чтобы запуск был удобнее:

- **Повторный старт быстрый.** Зависимости устанавливаются один раз: если Django
  и Pillow уже стоят, а `requirements.txt` не менялся, `pip` не запускается.
- **Не создаёт второе окружение.** Если рядом с папкой проекта уже есть `.venv`
  (так бывает, когда проект открыт в PyCharm), батник использует его.
- **Не воюет за порт.** Если порт занят (сервер уже запущен из PyCharm или
  вторым окном), батник предложит открыть работающий магазин в браузере
  или выбрать другой порт.
- **Сам предлагает создать администратора**, если в базе его ещё нет.
  Отказаться можно просто нажав Enter — тогда позже запустите `create_admin.bat`.
- **Браузер открывается, когда сервер уже слушает порт**, поэтому страница
  не встречает ошибкой подключения.

Чтобы остановить сервер — нажмите `Ctrl+C` в окне батника или закройте его.

Совет: сделайте ярлык — правый клик по `run.bat` → «Отправить» →
«Рабочий стол (создать ярлык)». Тогда запуск магазина будет в один клик
прямо с рабочего стола.

### Запуск из PyCharm (зелёной стрелкой)

Это тот же `runserver`, только без батника — сервер работает на вашем ПК.

**PyCharm Professional:**

1. `Run` → `Edit Configurations…` → `+` → `Django Server`.
2. Interpreter — `.venv` вашего проекта.
3. Host `127.0.0.1`, Port `8000`, `OK` — и запускайте.

**PyCharm Community** (отдельной Django-конфигурации там нет,
подходит обычная конфигурация Python):

1. `Run` → `Edit Configurations…` → `+` → `Python`.
2. `Script path` — путь к `manage.py` в папке проекта.
3. `Parameters` — `runserver`.
4. `Working directory` — папка проекта (там, где лежит `manage.py`).
5. Interpreter — `.venv`, `OK` — и запускайте.

Магазин откроется на <http://127.0.0.1:8000/>. Не держите сервер из PyCharm
и `run.bat` одновременно: оба занимают порт 8000. Если порт уже занят,
`run.bat` сам предложит открыть работающий магазин или выбрать другой порт.

### Ручной запуск (пошагово)

1. Установите [Python 3.12+](https://www.python.org/downloads/) (отметьте галочку «Add to PATH»).
   Django 6.1 требует Python 3.12 или новее — на более старых версиях
   зависимости не установятся.

2. Откройте папку проекта в терминале (PowerShell или «Командная строка»):

   ```
   cd путь\к\папке\GameZone
   ```

3. Создайте виртуальное окружение:

   ```
   py -m venv .venv
   ```

   Если лаунчер `py` не работает, используйте `python -m venv .venv`.
   Если `python` выводит ошибку про `WindowsApps\python.exe` — это подставла
   Microsoft Store, а не настоящий Python: установите Python с python.org.

4. Активируйте окружение:

   ```
   .venv\Scripts\activate
   ```

5. Установите зависимости (Django и Pillow):

   ```
   pip install -r requirements.txt
   ```

6. Примените миграции:

   ```
   python manage.py migrate
   ```

   Если вы изменяли модели, сначала выполните `python manage.py makemigrations`.
   Если изменений нет, команда сообщит «No changes detected» — это нормально.

7. Заполните базу демонстрационными категориями и товарами:

   ```
   python manage.py seed_data
   ```

   Команду можно запускать повторно: данные не дублируются, ничего не удаляется.
   С ключом `--if-empty` заполнение выполнится только при пустой базе
   (так работает `run.bat`, чтобы не затирать ваши правки в админ-панели).

8. Создайте администратора (пароль придумайте сами, в коде пароля нет):

   ```
   python manage.py createsuperuser
   ```

   Обратите внимание: символы пароля при вводе в консоли не отображаются —
   это стандартное поведение, просто набирайте пароль и нажимайте Enter.
   Если консоль не принимает ввод пароля, используйте `create_admin.bat` —
   там логин и пароль вводятся обычным видимым текстом.

9. Запустите сервер разработки:

   ```
   python manage.py runserver
   ```

10. Откройте в браузере:
    - магазин: <http://127.0.0.1:8000/>
    - админ-панель: <http://127.0.0.1:8000/admin/>

## Решение частых проблем

**Ошибка `no such table: auth_user` (или других таблиц) при входе в `/admin/`**

Значит, к базе данных не применялись миграции (сервер может запускаться,
но таблицы ещё не созданы). Выполните в папке, где лежит `manage.py`:

```
python manage.py migrate
python manage.py seed_data
```

Затем перезапустите сервер и создайте администратора (`create_admin.bat`
или `python manage.py createsuperuser`). Батник `create_admin.bat` теперь
и сам применяет миграции перед созданием администратора.

**Проект открыт в PyCharm**

Выполняйте команды в терминале PyCharm — той же виртуальной средой,
которой запускается сервер. Зависимости ставьте из `requirements.txt`:

```
pip install -r requirements.txt
```

Проект разработан и проверен на Django 6.1 (последняя ветка) и Python 3.12+.
Зависимости ставьте только из `requirements.txt` — там указана проверенная
ветка Django (`>=6.1,<7.0`). Держать одновременно сервер из PyCharm и `run.bat`
не нужно: оба занимают порт 8000. Если порт уже занят, `run.bat` это заметит
и предложит открыть работающий магазин в браузере либо запуститься на другом
порту (`run.bat 8080`).

**На хостинге сайт отвечает ошибкой 400 на все страницы**

Значит, `DJANGO_DEBUG=0`, но не задан `DJANGO_ALLOWED_HOSTS` — Django не знает,
какие домены считать своими. Теперь в этом случае проект не стартует и пишет
в лог понятное сообщение с примером. Задайте переменную на хостинге:

```
DJANGO_ALLOWED_HOSTS=ваш-сервис.onrender.com
```

**Сборка на хостинге ищет Dockerfile и не находит его**

Так выглядит сервис, созданный с рантаймом Docker. Либо перезапустите деплой
(`Dockerfile` в проекте есть), либо создайте сервис заново с рантаймом
**Python 3** — тогда используются команды из `render.yaml`.

**Ошибка про `WindowsApps\python.exe` при запуске батников**

Это подставла Microsoft Store, а не настоящий Python. Установите Python
с [python.org](https://www.python.org/downloads/) — батники автоматически
используют лаунчер `py` (установщик ставит его вместе с Python).

**Пароль при создании администратора «не вводится»**

Стандартный запрос `createsuperuser` скрывает символы и в некоторых
консолях Windows не принимает ввод. Используйте `create_admin.bat` —
логин и пароль набираются обычным видимым текстом.

## Изображения товаров

У товара есть необязательное поле `image` (ImageField). Демонстрационные товары
используют локальные SVG-иллюстрации из `shop/static/shop/images/` — поэтому
сайт полностью работает без загрузки картинок. Если изображение не загружено,
шаблоны показывают иллюстрацию категории через `Product.get_image_url()`.

Чтобы загрузить свою картинку, зайдите в админ-панель → Товар → поле «изображение».
Для этого требуется Pillow (уже есть в `requirements.txt`).

## Как вывести сайт в интернет

### Почему не Netlify

Netlify раздаёт статические файлы и serverless-функции на JavaScript, TypeScript
и Go. Python там доступен только на этапе сборки, поэтому запустить Django-сервер
на Netlify нельзя — это ограничение платформы, а не проекта. Магазину нужен
постоянно работающий процесс: база данных, сессии корзины, оформление заказов,
админ-панель.

На Netlify можно выложить только **статическую копию** страниц (витрину):
главная, каталог и карточки товаров будут видны, но корзина, оформление заказа,
поиск, фильтры и админка работать не будут — им нужен сервер.

Дальше — два бесплатных способа опубликовать именно **работающий** магазин.

### Вариант 1. Render — деплой из GitHub, бесплатно

Всё нужное уже лежит в проекте: `render.yaml`, `Procfile`, `.python-version`,
`requirements-prod.txt`, команда `ensure_admin` и боевые настройки
в `gamezone/settings.py`.

1. Проект должен лежать в репозитории GitHub. При создании сервиса выберите
   ветку, в которой находится код.
2. Откройте <https://render.com>, войдите через GitHub.
3. **New +** → **Blueprint** → выберите репозиторий. Render найдёт `render.yaml`
   и сам создаст сервис с нужными командами.
   (Можно и **New +** → **Web Service** — тогда команды возьмите из `render.yaml`:
   build — `pip install -r requirements-prod.txt && python manage.py collectstatic --noinput`,
   start — `python manage.py migrate --noinput && python manage.py seed_data --if-empty
   && python manage.py ensure_admin && gunicorn gamezone.wsgi:application`.)
4. В разделе **Environment** задайте три переменные:

   | Переменная | Что указать |
   |---|---|
   | `DJANGO_ALLOWED_HOSTS` | адрес сервиса, например `gamezone.onrender.com` |
   | `DJANGO_SUPERUSER_USERNAME` | логин администратора (придумайте свой) |
   | `DJANGO_SUPERUSER_PASSWORD` | пароль администратора (придумайте свой) |

   `DJANGO_DEBUG=0` и `DJANGO_SECRET_KEY` уже прописаны в `render.yaml`
   (ключ Render сгенерирует сам — в коде проекта паролей и ключей нет).
5. Дождитесь конца сборки. Render сам поставит зависимости, соберёт статику,
   применит миграции, добавит демо-товары, создаст администратора
   и запустит gunicorn.
6. Откройте `https://ваш-сервис.onrender.com/` и
   `https://ваш-сервис.onrender.com/admin/`.

**Если Render собирает проект как Docker.** При создании сервиса вручную можно
случайно выбрать рантайм Docker вместо Python — тогда в логе сборки будет
`failed to read dockerfile: open Dockerfile: no such file or directory`.
В проекте есть `Dockerfile`, поэтому достаточно перезапустить деплой
(**Manual Deploy** → **Deploy latest commit**). При желании рантайм можно
сменить на Python 3: **Settings** → **Build** → **Source** → **Edit** →
выбрать Python 3 и указать команды из `render.yaml`.

Честно об ограничениях бесплатного тарифа Render:

- сервис засыпает примерно после 15 минут без посетителей и просыпается
  около минуты — первый заход будет медленным;
- файловая система временная: при каждом новом деплое база создаётся заново.
  Миграции, демо-товары и администратор восстанавливаются автоматически
  (это делает start-команда), а вот товары, добавленные вами через админку,
  и оформленные заказы пропадут;
- чтобы данные жили постоянно, подключите бесплатный PostgreSQL
  (например, Neon или Supabase) и задайте переменную `DJANGO_DATABASE_URL`
  со строкой подключения — проект её понимает;
- загруженные через админку картинки хранятся на диске сервиса и тоже
  сбрасываются при деплое;
- трафик — 5 ГБ в месяц.

### Вариант 2. PythonAnywhere — бесплатно, база не пропадает

Здесь SQLite лежит на настоящем диске, поэтому добавленные товары и заказы
сохраняются. Сайт будет по адресу `ваш-логин.pythonanywhere.com`.

1. Зарегистрируйтесь на <https://www.pythonanywhere.com> (тариф Beginner — $0).
2. Загрузите файлы проекта: через вкладку **Files** или в консоли
   **Bash** командой `git clone`.
3. В консоли Bash, в папке проекта:

   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   .venv/bin/python manage.py migrate
   .venv/bin/python manage.py seed_data
   .venv/bin/python manage.py collectstatic --noinput
   .venv/bin/python manage.py createsuperuser
   ```

4. **Web** → **Add a new web app** → **Manual configuration** → версия Python
   3.12 или новее.
5. В настройках приложения укажите **Virtualenv** — путь к папке `.venv`.
6. Откройте **WSGI configuration file** и приведите его к такому виду
   (путь — к вашей папке проекта):

   ```python
   import os
   import sys

   path = '/home/ваш-логин/GameZone'
   if path not in sys.path:
       sys.path.append(path)

   os.environ['DJANGO_SETTINGS_MODULE'] = 'gamezone.settings'
   os.environ['DJANGO_DEBUG'] = '0'
   os.environ['DJANGO_SECRET_KEY'] = 'ваш-длинный-случайный-ключ'
   os.environ['DJANGO_ALLOWED_HOSTS'] = 'ваш-логин.pythonanywhere.com'

   from django.core.wsgi import get_wsgi_application
   application = get_wsgi_application()
   ```

   Этот файл живёт на сервере и не попадает в репозиторий, поэтому ключ
   в нём допустим. Никому не показывайте его и не публикуйте.
7. В разделе **Static files** добавьте соответствие: URL `/static/` →
   директория `/home/ваш-логин/GameZone/staticfiles/`.
8. Нажмите **Reload** и откройте сайт.

Ограничения бесплатного тарифа: один сайт, 512 МБ диска, адрес только
на `pythonanywhere.com` (свой домен — платно), исходящий доступ в интернет
только к разрешённым адресам, и примерно раз в месяц нужно заходить
и нажимать «продлить» (Extend), иначе сайт останавливают.

### Настройки, которые обязательно задать при публикации

1. `DJANGO_DEBUG=0` — без этого в интернет уйдут технические страницы ошибок
   с кодом и настройками.
2. `DJANGO_SECRET_KEY` — свой длинный случайный ключ, не тот, что в коде.
3. `DJANGO_ALLOWED_HOSTS` — домен вашего сайта (через запятую, если их несколько).
   Домены из этой переменной автоматически попадают в `CSRF_TRUSTED_ORIGINS`,
   поэтому формы корзины и оформления заказа работают по HTTPS без 403.
4. Статика: `python manage.py collectstatic --noinput` и её раздача
   (WhiteNoise на Render, сопоставление `/static/` на PythonAnywhere).
5. Пароль администратора — только в переменных окружения
   (`DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_PASSWORD`), никогда в коде.
6. `db.sqlite3`, `.venv` и ключи не коммитятся — это уже настроено в `.gitignore`.

При `DEBUG=False` проект дополнительно включает HTTPS-редирект, защищённые
cookies сессий и CSRF, а также HSTS на один час — это стандартный набор
для учебного сайта за HTTPS-прокси.

### Проверить боевой режим локально

Перед публикацией полезно убедиться, что всё работает при `DEBUG=0`.
В PowerShell, в папке проекта:

```
pip install -r requirements-prod.txt
$env:DJANGO_DEBUG="0"
$env:DJANGO_SECRET_KEY="длинный-случайный-ключ-для-проверки"
$env:DJANGO_ALLOWED_HOSTS="127.0.0.1,localhost"
$env:DJANGO_SSL_REDIRECT="0"
python manage.py collectstatic --noinput
python manage.py migrate
python manage.py runserver
```

`DJANGO_SSL_REDIRECT="0"` нужен только для локальной проверки: на хостинге сайт
работает по HTTPS и редирект там включён, а локально он отправил бы браузер
на несуществующий `https://127.0.0.1:8000`.

Сайт откроется на <http://127.0.0.1:8000/> в том же режиме, в каком будет
работать на хостинге. Вернуть обычную разработку: закройте окно и запустите
`run.bat` (переменные окружения живут только в этом окне PowerShell).

## Честные оговорки

- Цены и товары — демонстрационные, это не актуальные рыночные предложения.
- Оплата не подключена: заказ только сохраняется в SQLite.
- Email-рассылка не настроена: обращения с формы связи сохраняются в базе,
  письма не отправляются.
- Статус «По популярности» в каталоге — демонстрационный критерий
  (рекомендуемые товары выводятся первыми), реальная статистика продаж не ведётся.
